# Golden Eval Set — Build Rules

Generated by `src/rag_sn_in/eval/build_golden_eval.py` from the chunks in
`data/processed/chunks/*.jsonl`. One file per document year, ≥500 golden
(answerable-only) questions per file. irrelevant questions.

## 1. Input filtering (usable chunks)

A chunk is eligible if:

- `text_token_count >= 70` (skips truncated orphan chunks),
- it is not a pure table/noise chunk (no usable prose),
- its `section_path` yields a section label (directly or via fallback to the
  last non-`CHAPITRE` path part).

## 2. Candidate question families

For every usable chunk, several families are attempted. A family only fires
when its content signal is found in the chunk **and** the topic appears in the
answer (grounding check).

| Family | Trigger in chunk text | Example shape |
|---|---|---|
| `definition` | definition-signal sentence (« est défini comme », « désigne »…) | « C'est quoi la DANC ? » |
| `process` | procedure signal (« marche à suivre », « doit transmettre »…) | « Quelle est la marche à suivre pour … ? » |
| `obligation` | « il est obligatoire / interdit / requis »… | « Qu'est-ce qui est obligatoire concernant … ? » |
| `deadline` | explicit date / « au plus tard » / « avant le » | « Quelle est la date limite pour … ? » |
| `amount` | « € », « % », « montant », « redevance » | « Quel montant pour … ? » |
| `condition` | « dans le cas où », « sous condition », « si » | « Dans quel cas … ? » |
| `actor` | « SNCF Réseau », « le gestionnaire », « l'entreprise ferroviaire »… | « Qui est responsable de … ? » |
| `contact` | email/URL + contact verb (cap 30/file) | « Qui contacter pour … ? » |
| `system` | acronym pattern « le système XXX » | « À quoi sert le système TVM ? » |
| `factual` | lead sentence containing the topic | « Que dit le DRR 2026 à propos de … ? » |
| `factual` (overview) | none — works for every section, even without a "nice" topic | « Que précise le DRR 2025 dans la section « … » ? » |
| `list` | enumeration (« - », « : » + items) | « Quelles catégories … énumère-t-il ? » |
| `table` | markdown table rows | « Quels lignes/colonnes le tableau … présente-t-il ? » |
| `section` | section number only (no topic needed) | « Que prévoit la section 5.6.6.2 du DRR 2025 ? » |
| `multi_chunk` | two consecutive same-doc chunks, different section labels, ≤2 pages apart | « Que faut-il retenir conjointement sur « A » et « B » ? » |

## 3. Topic rules

- A "nice" topic = section label, 10–80 chars, not generic
  (« introduction », « généralités »… blocked), not raw numbering.
- Long ALL-CAPS labels are recapitalized for readability.
- Most families require ≥2 topic content-words in the answer
  (the overview family requires ≥1).

## 4. Per-question quality gates

Every candidate is kept only if:

- question ≤ 22 words, ≥ 18 chars,
- question matches no banned pattern (meta-questions, « paragraphe »,
  boilerplate…),
- gold answer is 50–420 chars, fully grounded: ≥ 78% of the answer's content
  tokens must appear in the gold chunk (min 6 tokens),
- no extraction artifacts (`[TABLE]`, `[section_header]`) remain in the
  question or the answer.

## 5. Deduplication rules

- Exact dedupe on normalized question text (lowercase, accents/punct stripped).
- Near-dedupe: Jaccard ≥ 0.8 on question token sets (year markers ignored)
  → the second one is dropped.
- At most one question per `(chunk_id, question_type)`.
- Frame diversity: max 3 questions per identical template per file
  (4 for `multi_chunk`).

## 6. Per-type caps (diversity guard)

definition 90 · process 85 · obligation 60 · deadline 70 · amount 70 ·
condition 70 · actor 50 · contact 30 · system 55 · factual 175 · list 60 ·
table 45 · section 75 · multi_chunk 80.

Selection targets 560 questions/year, stopping at the cap of each type.

## 7. Cross-year twin rule

A question is eligible for cross-year gold ids only if it is **not
year-pinned** (the question does not mention the year and the answer contains
no year/date/day reference). For such questions, chunks from the other two
years sharing the same section label and ≥ 0.25 content overlap are appended
to `gold_chunk_ids` (max 4 ids total, `notes += "; cross-year twins"`).
Year-pinned questions keep same-year golds only.

## 8. Output schema (exact key order)

```json
{"id", "question", "gold_chunk_ids", "gold_answer", "question_type",
 "difficulty", "requires_year": true, "answerable": true, "notes",
 "collection": "DRR_SNCF", "match_field": "payload.id",
 "document_id", "section_path", "page_start", "page_end"}
```

- `gold_chunk_ids[0]` always belongs to the row's `document_id`.
- Generation is deterministic (seeded RNG per document).

## 9. Post-build validation (must all pass)

- ≥ 500 rows per file,
- schema keys exact, `answerable`/`requires_year` true on every row,
- zero duplicate questions, zero empty answers/questions,
- every `gold_chunk_ids` exists in the current chunk files,
- every non-`multi_chunk` answer re-passes the 78% grounding check.

## Operational rule

Chunk ids are positional (`<doc>_chunk_NNNN`). **Any re-chunking renumbers
ids → re-index Qdrant AND regenerate this eval set**, otherwise retrieval
metrics silently compare against stale content (no error, wrong results).
